## What this cycle did

The smallest end-to-end path that makes the OS real instead of registry-only:

1. **`packages/core`** (still pure; relative imports only)
   - `validateProfile` against the ProjectProfile assessment rules
   - `classifyRisk` ruleset 0.1.0
   - `selectModules(profile, moduleRegistry, capabilityRegistry, platformPhase)` per `tooling/CAPABILITY_REGISTRY.md`
   - `buildProfile` from plain-English idea + short form (explicit ASSUMED defaults; no model)
   - `compileProjectOs` emits README, PROJECT.md, AGENTS.md stub, ARCHITECTURE.md stub, `state/CURRENT_STATE.md`
   - Untrusted idea text is fenced as data, never interpolated into the AGENTS stub
   - Deterministic STORE ZIP (`buildZip`)
2. **`POST /os/api/compile`** — profile JSON or `{ idea, form }` → ZIP, or `format=json` file listing. `GET /os/api/healthz` unchanged.
3. **`/os` UI** — paste an idea or fill the short profile, compile, download ZIP. Copy says foundation demo, not the full OS.
4. **Tests:** core goldens + shuffle-invariance + compile determinism; server happy path and invalid profile.

Capability registry stays at 301. No metered AI, no publish, no secrets.
